How a review runs驗證流程

Research, argue, then decide.

先研究，再辯論，最後下決定。

01

Check providers

檢查 provider

check_providers.py looks for codex, agy or gemini, and grok, and sends each one a one-line prompt. If a CLI is installed but cannot answer, Claude reports it as 測不到帳號 (account not reachable).

check_providers.py 會找 codex、agy 或 gemini，以及 grok，並各送一句測試提示。裝了卻無法回應的 CLI，Claude 會回報「測不到帳號」。

02

Research first

先做研究

With web tools available, Claude gathers competitors, pricing, demand, platform limits, and policy constraints. Later rounds must separate evidence from assumptions.

有網路工具時，Claude 會先蒐集競品、價格、需求、平台限制與政策限制。之後每一輪都要分清楚哪些是證據、哪些是假設。

03

Argue in rounds

分輪辯論

Round 1 is first positions, the middle rounds clash, and the last round converges. After round 1, every personality must answer an earlier point.

第 1 輪各自表態，中間幾輪互相攻防，最後一輪收斂。第 1 輪之後，每個個性都要回應先前的論點。

04

Decide and print

下結論、印報告

final.md holds the verdict, confidence, and kill criterion. report.html shows the conclusion first, then the idea and every round, with a Print / Save PDF button.

final.md 記下結論、信心分數與停止條件；report.html 先放結論，接著是點子與每一輪，並附上 Print / Save PDF 按鈕。

What you get你會得到什麼

A decision aid, not encouragement.

要的是決策依據，不是加油打氣。

Most of the skill is instructions in SKILL.md. Three small Python scripts handle the mechanical parts: the provider check, the review folder, and the report.

這個 skill 大部分是 SKILL.md 裡的指示；三個小型 Python scripts 負責機械性的部分：provider 檢查、review 資料夾與報告。

01

Four personalities, not four models

四種個性，不是四個模型

Optimist, Skeptic, Pragmatist, and Synthesizer are thinking styles, not departments, roles, or separate models. Each gets its own section in every round file.

Optimist、Skeptic、Pragmatist、Synthesizer 是思考風格，不是部門、職務，也不是不同的模型。每一輪的檔案裡，各自都有一段。

SKILL.md
02

Native when possible, labeled when simulated

能用原生就用，模擬時會標明

Codex, Gemini, and Grok are used through their CLIs when they answer. Otherwise Claude asks once for an API key; without one, it simulates that style and labels it, as in Claude 模擬 Codex (Claude simulating Codex).

Codex、Gemini、Grok 的 CLI 能回應時就直接使用；不行的話，Claude 只問一次 API key，沒有 key 就模擬該風格並標示出來，例如「Claude 模擬 Codex」。

scripts/check_providers.py
03

Files you can keep

留得下來的檔案

Unless you ask for inline-only output, each review writes input.md, one file per round, final.md, report.md, and a static report.html you can print or save as PDF.

除非你只要在對話裡看結果，每次 review 都會寫出 input.md、每輪一個檔案、final.md、report.md，以及可以列印或存成 PDF 的靜態 report.html。

Design decisions設計取捨

Why it is shaped this way.

為什麼這樣設計。

01

Personalities instead of model seats

用思考個性，而不是模型席位

The web version, ai-brainstorming, gives five models a seat each through OpenRouter. Inside Claude Code, four personalities need no extra accounts, and other providers are used only when their CLI answers or you give a key.

網頁版的 ai-brainstorming 透過 OpenRouter 讓五個模型各坐一席。在 Claude Code 裡，四種思考個性不需要額外帳號，其他 provider 只在 CLI 能回應或你提供 key 時才會用到。

02

Ask once, then keep going

只問一次，然後繼續

A missing key should not stall a review. The skill asks one time whether you have a key and whether you prefer the provider's own API or OpenRouter; if none is given, it continues on Claude simulation instead of waiting.

缺 key 不該讓整個 review 停下來。這個 skill 只會問一次：你有沒有 key、要用原廠 API 還是 OpenRouter；沒有提供，就改用 Claude 模擬繼續跑，不會一直等。

03

Conclusion first, rounds after

先放結論，再放過程

The report opens with the verdict and kill criterion, so a reader who stops after one page still gets the decision. The rounds follow as the supporting record.

報告一開頭就是結論與停止條件，只看第一頁的人也拿得到決定；每一輪的內容放在後面，當作佐證紀錄。

Clone into your personal skills folder. For one project only, use that project's .claude/skills/ instead. On Windows, the README has a PowerShell version.

clone 到個人的 skills 資料夾；只想用在單一專案的話，改放到該專案的 .claude/skills/。Windows 的 PowerShell 版本請看 README。

Honest status誠實的現況

Where it stands.

目前的樣子。

Built over six commits from June 14 to 16, 2026, as an open-source skill for the 自由工坊 Discord community and the 個人 IP 陪跑計畫. The skill has not changed since, and there are no releases; install from main.

這是 2026 年 6 月 14 日到 16 日、共 6 個 commit 寫成的開源 skill，為「自由工坊」Discord 社群與個人 IP 陪跑計畫而做。之後 skill 本身沒有再更新，也沒有 release，請直接從 main 安裝。

2026-09-30 實測

  • init_review.py creates the timestamped folder, input.md, one file per round, and final.md; --rounds accepts only 5, 12, or 16
  • init_review.py 會建立帶時間戳記的資料夾、input.md、每輪一個檔案與 final.md；--rounds 只接受 5、12、16

  • render_report.py 會寫出 report.md 與靜態的 report.html，附 Print / Save PDF 按鈕，各部分之間會分頁
  • check_providers.py finds codex, agy or gemini, and grok on PATH, and lists key variable names without their values
  • check_providers.py 能在 PATH 上找到 codex、agy 或 gemini，以及 grok，而且只列出 key 變數名稱、不印出值

Limits and not yet

限制與尚未完成

  • The review is instructions in SKILL.md, not code, so its structure and quality depend on Claude following them
  • review 是 SKILL.md 裡的指示，不是程式碼，結構與品質取決於 Claude 有沒有照做
  • No API client: if you provide a key, how the API gets called is left to Claude in that session
  • 沒有 API 用戶端：提供 key 之後怎麼呼叫 API，交給當下 session 裡的 Claude
  • A failed agy smoke test is inconclusive, because agy -p can exit 0 with empty output when piped
  • agy 測試失敗不能下定論，因為 agy -p 在管線中可能以結束碼 0 結束卻沒有輸出
  • The report renderer does not support tables or code blocks, and always marks the HTML as zh-Hant
  • 報告產生器不支援表格與程式碼區塊，HTML 也一律標示為 zh-Hant
  • No tests, CI, or releases
  • 沒有測試、CI 或 release
